# Golden dataset (`golden_es_v2.csv`)

111 items, Spanish. Fixed reference for every evaluation run. `golden_es.csv` is v1 (120 items), kept to compare old runs.

## Changes in v2

- Removed q039 (E labels unrelated to the query), q018 (no Orbea or e-bike in the catalog) and u007 (a product search, not out of scope).
- Removed the six color follow-ups f001-f006 ("¿Y en negro?"): too vague to test. The set has no `follow_up` items now.
- Follow-up histories: the assistant turn now names real products instead of a placeholder.
- Opik dataset is `rag-ecommerce-golden-v2`.

| Column | Meaning |
|---|---|
| `id` | Unique id (`q` ESCI query, `f` follow-up, `u` unanswerable, `a` adversarial) |
| `input` | The user question |
| `expected_product_ids` | ESCI label **E** products, separated by `\|` |
| `acceptable_product_ids` | ESCI label **S** products (also a good answer, max 5) |
| `expected_output` | Reference answer. Answerable: a template with the product titles and ids. Others: the fixed refusal |
| `answerable` | `true` / `false` |
| `question_type` | `exact`, `attribute`, `broad`, `brand`, `follow_up`, `typo`, `unanswerable`, `adversarial` |
| `source` | `esci` (query as in ESCI) or `manual` (typo / follow-up / hand-written) |
| `history` | JSON list of previous turns (follow-ups only) |

## How the items were chosen

`python -m scripts.build_golden` (seed 7) picks 84 real ESCI queries (spanning short to long) that have 1-6 E products, turns 6 of them into typo variants and 6 more into follow-ups ("¿Y en negro?" with the base query as history). It adds 18 unanswerable questions (price, stock, delivery, returns, other topics) and 12 adversarial ones (prompt injection, system-prompt leak), all hand-written. Mix: ~70% answerable, 15% unanswerable, 10% adversarial, 5% follow-up.

`golden_queries.txt` lists the ESCI queries used; `scripts.sample_catalog` always keeps their E and S products in the catalog.

## Rules

- Add an item: append a row, run `python -m src.evaluation.dataset` (validates ids against the catalog).
- Sync Opik after editing the CSV: `python -m src.evaluation.dataset --upload`. It deletes Opik items removed from the CSV and inserts the new ones, so the evaluator's item ids match the file.
- Never edit the set to make a score better. Changes go in a PR with the reason.
